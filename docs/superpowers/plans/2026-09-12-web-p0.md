**Goal:** 在已验证的工程骨架上实现网页版 P0：后端全部 REST 接口（88 个中除同步推拉与快照外的 79 个）与 23 张表，桌面壳全部页面；安卓与同步接口后置，但每次可同步写入都按设计写入变更日志，保证后续接入同步时无需改业务代码。

**Architecture:** 按切片纵向推进，每个切片交付“契约 → 生成 → 模块（含单元测试）→ PostgreSQL 适配（sqlc）→ HTTP 处理器 → 集成测试 → 桌面壳页面”。资源模型通过 oapi-codegen 的 `x-go-type` 直接指向业务类型（评审 S11），同一个 Go 类型既是 GET 响应也是同步日志快照。统一写事务放在 pgcore：账号锁、收据去重、字段级合并、变更日志、River 事务入队。

**Tech Stack:** 与工程骨架一致；新增 golang-jwt/jwt v5、x/crypto（argon2id）、aws-sdk-go-v2 S3（OSS 与 MinIO 通用，开发用 MinIO）、x/image（webp 解码）、goexif；前端 ECharts（vue-echarts）、高德 JS API 2.0 加载器。

**Spec:** `docs/api/2026-09-11-P0接口设计.md` v0.3、`docs/database/2026-09-11-P0数据库表结构设计.md` v0.3、`docs/architecture/2026-09-11-P0接口与数据设计总览.md` v0.3、`docs/requirements/2026-09-10-P0核心需求.md` v0.3。

## 全局约束

- 全部写接口：Idempotency-Key（UUID）必填；PATCH 用 If-Match 基线版本并按 changed_fields 字段级合并；DELETE、动作、PUT 要求版本相等；创建由客户端给 id。
- 可同步写事务：READ COMMITTED，第一条语句 `SELECT ... FOR UPDATE account_sync_state`；成功后写 mutation_receipts 与 sync_changes（含 changed_fields）；账号级实体的 trip_id 为空。
- 错误代码只用接口设计 1.4 清单；跨账号或跨旅行 ID 一律 404。
- 金额：Money 十进制字符串，服务端按币种小数位规范化；退款不超过原支出；净额 = 支出 − 退款。
- 会话：JWT 15 分钟（HS256，kid），refresh `<session_id>.<secret>` 30 天轮换、60 秒宽限；网页刷新凭证走 `__Host-tripfolio_refresh` Cookie + CSRF 双提交 + Origin 校验；Argon2id m=64 MiB, t=3, p=1，并发上限。
- 时间戳一律由应用时钟传入 SQL，不依赖数据库 `now()`（数据库与应用时钟可能有偏差，会触发 `updated_at >= created_at` 约束）。
- 文件：创建资产即返回上传授权；引用不要求 ready；worker 以 ETag 条件复制到最终键；下载授权原图 60 秒、缩略图 15 分钟、批量最多 100。
- 桌面壳只服务宽屏浏览器；所有页面通过 openapi-fetch 客户端访问 API，不直接 fetch。
