# 旅行分享设计

日期：2026-09-15。状态：设计已确认，待实施（网页版实施计划切片 S）。

## 1. 背景与范围

用户可以为指定旅行生成一条分享链接，任何人打开链接**无需登录**即可查看这趟旅行的行程与地图，且**只能查看**。

分享在 [P0 核心需求](../../requirements/2026-09-10-P0核心需求.md) 中原属「后续扩展」，本设计把它提前纳入交付范围。它引入一条全新的、不依赖账号会话的访问通道，是 P0 之外的新增子系统，因此单独立文档。

### 交付范围

- 旅行详情页新增分享入口：生成链接、复制、重新生成、关闭。
- 访客页 `/s/<token>`：旅行基本信息、按天编排的行程列表（含站间距离）、地图点位与道路路线。
- 每趟旅行至多一条分享链接，开关式；重新生成使旧链接立即失效。

### 明确不做

- 不分享账目、统计、行李清单、待办、相册、预订与资料。
- 不提供访客评论、点赞或任何写入。
- 不做多条链接、有效期、访问密码、访问者名单。
- 不做访客侧的数据快照：访客读取的是**当前实时数据**，主人改了行程，访客刷新即见最新。理由是个人旅行应用的分享语义就是「把我现在的行程给你看」；既有的 `data_snapshots` 子系统是为离线同步与导出设计的，复用到分享上只会引入无谓的生成任务与过期管理。
- 不做微信／社交平台的分享卡片（`og:*` 元信息）。链接本身可用，卡片留作后续。
- 安卓 Capacitor 壳不承载访客页。分享链接是网页，由浏览器打开。

## 2. 设计决策

### 2.1 令牌机制：不透明随机令牌 + 查库

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| **不透明随机令牌 + `trip_shares` 表** | 撤销即时生效；URL 短；查库一次，与现有会话校验同量级 | **采用** |
| 签名 JWT 自包含 | 无需查库，但撤销要另建黑名单表，反而更复杂；令牌数百字符，链接难传 | 否决 |
| 用 `trip_id` 作 URL + `trips.is_public` 列 | 改动最小，但 `trip_id` 是登录态 URL 里出现过的已知值，泄露即永久可猜；且**关闭后重开换不了地址**，无法满足「重新生成使旧链接失效」 | 否决 |

令牌为 16 字节密码学随机数的 base64url 无填充编码，22 个字符，128 位熵，不可枚举。

### 2.2 令牌以明文存储

`account_sessions` 只存 refresh token 的 SHA-256 摘要。`trip_shares` **存明文**，这是刻意的差异：

只存摘要意味着链接只能在生成的那一刻显示一次，用户关掉页面或换台设备就再也复制不出来，只能反复「重新生成」——对分享链接是糟糕的体验。代价是数据库里多一个可直接利用的凭据，但它的权限上限只是「读一趟旅行的行程骨架」，与能换取 access token 的 refresh token 不在一个量级。

同理，`account_sessions` 的摘要列不建索引（所有查找按主键进行），而 `trip_shares.token` **就是**访客侧的查找键，必须建唯一索引。

### 2.3 分享不进同步体系

`trip_shares` 的写入**不写 `sync_changes`、不进快照与导出、不递增 `trips.version`**。

递增 `trips.version` 会让所有已登录客户端误判旅行内容发生变化并触发重拉，而分享开关根本不是旅行内容。它的定位与 `account_sessions` 一致：账号的访问控制状态，不是业务资源。

因此分享的四个写接口**不要求 `Idempotency-Key`，也不要求 `If-Match`**，落在[接口设计](../../api/2026-09-11-P0接口设计.md) 1.2 的「除单独说明的认证/会话/临时授权接口外」豁免内。

### 2.4 访客算路走封闭接口，不复用 `/geo/routes`

`/geo/routes` 的起终点是请求参数里任意指定的坐标。若允许分享令牌调用它，分享链接就成了一个对外开放的高德算路代理：任何人拿到链接即可计算任意两点的路线，消耗的是本站配额。限流只能压速率，压不住性质。

改为封闭接口 `GET /public/routes?mode=`：服务端按该旅行的行程顺序自行取点算路，**访客侧没有任何坐标注入点**。附带好处是整趟结果可按 `share_id + mode + 行程指纹` 整体缓存，多访客访问同一链接时命中率远高于逐段缓存。

代价是相邻路段的推导逻辑（排序、跳过无坐标点、跨日接续）需要在 Go 侧实现一份，规则很薄。

### 2.5 公开模型独立定义

访客侧的资源模型**不复用** `Trip` 与 `ItineraryItem`，而是独立定义的固定字段集。这样将来给 `itinerary_items` 加字段不会自动流到公开接口。见 4.3。

## 3. 数据模型

### 新表 `trip_shares`：旅行分享链接

| 字段 | PostgreSQL 类型 | 空值 / 默认 / 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | 主键 | 分享记录 ID，服务端生成 |
| account_id | uuid | NOT NULL | 所属账号，外键 accounts.id ON DELETE CASCADE |
| trip_id | uuid | NOT NULL | 复合外键 (account_id, trip_id) → trips(account_id, id) ON DELETE CASCADE |
| token | varchar(22) | NOT NULL；UNIQUE | 分享令牌明文，16 字节随机数的 base64url 无填充编码 |
| created_at | timestamptz | NOT NULL | 首次开启时间，由应用时钟传入 |
| rotated_at | timestamptz | 可空 | 最近一次重新生成的时间 |
| last_viewed_at | timestamptz | 可空 | 最近一次访客读取旅行信息的时间，每次读取时更新 |
| view_count | bigint | NOT NULL DEFAULT 0 | 访客读取次数，供主人判断链接是否仍在被使用 |

键与关联：

- PK(id)；UNIQUE(token) 供访客侧按令牌定位；UNIQUE(account_id, trip_id) 落实「每趟旅行至多一条」。
- 两个外键均 ON DELETE CASCADE：旅行被永久清理或账号被注销时，分享记录随之消失，无需额外清理任务。

规则：

- 关闭分享是**物理删行**。分享不参与同步，不需要软删除，也不需要 `entity_tombstones`。
- 重新生成是 `UPDATE token, rotated_at`，旧令牌**立即失效、无宽限期**。这与 refresh token 的 60 秒宽限不同：分享链接不存在并发轮换导致响应丢失的场景。
- `last_viewed_at` 与 `view_count` 只在访客读取旅行信息（`GET /public/trip`，每次页面加载一次）时 best-effort 更新；行程列表与算路不计数，更新失败不影响读取结果。
- 旅行进入回收站时**不删除**分享记录（恢复后链接应继续可用），访客侧按 7.1 返回 410。

## 4. 接口契约

新增 `packages/contracts/openapi/v1/paths/shares.yaml` 与 `schemas/share.yaml`。接口总数 **89 → 96**。

### 4.1 主人侧（`bearerAuth`）

| 方法 | 路径 | operationId | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| GET | /trips/{trip_id}/share | getTripShare | TripShare | 未开启返回 404 SHARE_NOT_FOUND |
| PUT | /trips/{trip_id}/share | enableTripShare | TripShare | 开启；已开启则原样返回，天然幂等 |
| POST | /trips/{trip_id}/share/rotate | rotateTripShare | TripShare | 重新生成令牌，旧链接立即失效 |
| DELETE | /trips/{trip_id}/share | disableTripShare | 204 | 关闭分享 |

不带 `Idempotency-Key`、不带 `If-Match`（见 2.3）。跨账号或不存在的 `trip_id` 返回 404 `RESOURCE_NOT_FOUND`；回收站中的旅行返回 410 `TRIP_DELETED`。

`TripShare` 字段：`id`、`token`、`url`、`created_at`、`rotated_at`、`last_viewed_at`、`view_count`。

`url` 由服务端按配置的网页站点根地址拼出完整分享地址，客户端不参与拼接——与对象存储键「客户端不参与拼接」的既有约定一致。站点根地址由新增配置项 `TRIPFOLIO_WEB_BASE_URL` 提供；生产环境缺失即启动失败，开发环境缺省为 `http://localhost:5173`。

### 4.2 访客侧（`shareAuth`）

`shareAuth` 在 OpenAPI 中声明为 `type: apiKey, in: header, name: Authorization`，格式 `Share <token>`。

| 方法 | 路径 | operationId | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| GET | /public/trip | getSharedTrip | PublicTrip | 分享旅行的基本信息 |
| GET | /public/itinerary-items | listSharedItineraryItems | Page\<PublicItineraryItem\> | 按 scheduled_on、sort_order、id 排序 |
| GET | /public/routes | getSharedRoutes | PublicRoutes | 整趟相邻路段的道路距离与时长 |

行程列表沿用既有的键集分页（`limit` 默认 50、上限 100）。访客页需要整趟数据，由前端循环翻页读全，复用既有 `listAllItineraryItems` 的做法，不为分享单开一个不分页的接口。

`/public/routes` 的 `mode` 取 `driving` / `walking` / `cycling`，非法值在请求上游前拒绝为 422，与 `/geo/routes` 的既有校验一致。

令牌放**请求头而非 API 路径**：这样它不会进入服务端 access log，也不会经由 Referer 泄露给高德等第三方。浏览器地址栏仍是 `https://<站点>/s/<token>`，因为前端路由需要它——这与飞书、Notion 的分享链接做法一致。

### 4.3 公开资源模型

```
PublicTrip              name, destination, start_date, end_date, timezone

PublicItineraryItem     id, scheduled_on, sort_order, title, kind,
                        place_name, address, latitude, longitude,
                        planned_start_local, planned_end_local,
                        planned_duration_minutes

PublicRoutes            mode,
                        legs[]: from_item_id, to_item_id,
                                distance_meters, duration_seconds,
                                path[]: GeoCoordinate
                        failed_leg_count, unlocated_item_count
```

刻意排除：`notes`、`actual_notes`、`estimated_amount`、`status`、`actual_start_local`、`actual_end_local`、`version`、`account_id`、`trip_id`、`created_at`、`updated_at`，以及主人的昵称、邮箱与头像。旅行层面不给 `notes`、`budget_amount`、`currency_code`。

`PublicRoutes` 只返回成功算出的路段，不返回总里程与总时长——由前端对成功路段求和并标明「仅含已算出的路段」，与[高德地图与行程路线](../../architecture/2026-09-14-高德地图与行程路线.md)既有规则一致，不把失败路段静默计入。

### 4.4 新增错误代码

`SHARE_NOT_FOUND`（404），需在接口设计 1.4 的错误代码清单登记。其余复用既有的 `TRIP_DELETED`（410）、`RESOURCE_NOT_FOUND`（404）、`RATE_LIMITED`（429）、`DEPENDENCY_UNAVAILABLE`（503）。

## 5. 后端实现

### 5.1 分层

- `modules/travel/share`：分享的业务规则与状态机（开启、重新生成、关闭、按令牌解析），令牌生成，端口定义。不导入 transport、adapters。
- `adapters/postgres/travel/share` + sqlc 查询：`trip_shares` 的读写。
- `transport/httpapi/middleware/share.go`：`Authorization: Share <token>` 的解析中间件。
- `transport/httpapi/share.go`、`public.go`：主人侧与访客侧处理器。
- bootstrap 显式装配；`Deps` 新增 `Shares *share.Service`。

### 5.2 认证通道

新增中间件 `middleware.Share`，解析 `Authorization: Share <token>`，按令牌查表得到 `(account_id, trip_id, share_id)`，构造 **独立类型** `share.Viewer` 放入 **独立的 context key**。

**这是整个功能的安全核心，有一条不能妥协的规则：**

> `share.Viewer` 绝不写入 `actor.Actor` 上下文。

所有既有业务处理器都从 `actor.FromContext` 取身份、取不到即 401。只要分享身份走独立类型与独立 key，分享令牌就在**类型层面**无法触达任何一个既有读写接口。权限边界由「拿不到身份」保证，而不是由每个接口逐一判断——后者只要漏掉一个接口就是越权漏洞。

中间件挂载方式：`router.go` 的 `isPublic` 改为前缀感知，`/public/` 下的路径视为不要求 Bearer，使 `middleware.Auth` 放行；随后 `middleware.Share` 对 `/public/` 路径强制校验分享令牌，缺失或无效返回 401。作为纵深防御，`middleware.Share` 在处理 `/public/` 请求时**主动剥离上下文中可能存在的 `actor.Actor`**（登录用户也可能打开分享链接并携带 Bearer），确保公开处理器绝无可能读到账号身份。

`middleware.Share` 同时校验主人账号状态：账号处于 `deleting` 时返回 403，与 `middleware.Auth` 的判断保持一致。

### 5.3 读取路径复用既有仓储

既有仓储方法的签名本来就要账号 ID，例如 `itinerary.Repo.List(ctx, accountID, tripID, ...)`。访客读取时传入从 `trip_shares` 行解析出的**主人的** `account_id` 即可。

**不新写任何「不带账号过滤」的 SQL。** 这类查询一旦存在于代码库中，就是长期的越权隐患，将来任何人误用都会绕过账号隔离。

### 5.4 访客算路

`GET /public/routes` 的服务端流程：

1. 按 `(scheduled_on, sort_order, id)` 读出该旅行全部有效行程项目。
2. 过滤出经纬度非空的点，依次两两成段；无坐标的点计入 `unlocated_item_count`，不打断相邻关系（前一个有坐标的点与后一个有坐标的点直接成段）。
3. 整趟结果按 `share_id + mode + 行程指纹` 缓存 5 分钟，指纹为有序 `(id, latitude, longitude)` 序列的 SHA-256。行程一改，指纹变化，缓存自然失效。
4. 未命中整趟缓存时逐段调用既有的 `geo.Service`，复用其按有序起终点与模式的 5 分钟单段缓存。
5. 单段失败不中断后续路段，计入 `failed_leg_count`。
6. 全局日上限耗尽时整个接口返回 503 `DEPENDENCY_UNAVAILABLE`，由前端降级为示意连线。

限流键为 `share_id + 客户端 IP`，复用 `adapters/ratelimit`。`/geo/*` 保持仅 Bearer，不接受分享身份。

## 6. 前端实现

### 6.1 路由与布局

```
/s/:token    meta: { public: true, share: true }
```

`App.vue` 目前无条件渲染 `<ShellComponent />`。改为：命中 `route.meta.share` 时渲染独立的 `ShareLayout`，**完全不挂载 `DesktopShell` / `MobileShell`**。

于是导航栏、账号菜单、回收站入口、路由守卫、全部编辑对话框根本不会进入访客页的 chunk——权限边界由「没有加载」保证，而不是「隐藏起来」。附带好处是访客首屏不必拖进整个桌面壳与 Element Plus。

访客页不走 `pickShell`，在单页内以容器宽度自适应排版，提供「行程 / 地图」两个视图切换。

两个视图与主人侧的对应页面保持一致，站间距离的文案与呈现规则直接对齐 `ItineraryTab.vue` 与 `TripMapTab.vue`：

- 行程视图对齐「相邻地点路程」：每个有坐标的站点在其后一行给出「下一站 · <站名>」与该出行方式下的距离、用时，跨日接续标「（跨日接续）」，中间夹有无坐标项目时标「（中间 N 项尚未定位）」，并提供同一组出行方式切换（驾车／步行／骑行）。
- 地图视图对齐「沿途各站」：按行程顺序列出每一站及其到下一站的距离与用时（同样标注跨日接续与中间未定位项目），点击可在地图上定位；汇总区给出已定位站数、已算路段里程与预计用时。
- 地图视图同样提供主人侧的日期范围筛选（整趟旅行／单日）：单日只显示该天的点位，连到次日的路段随之消失，汇总与沿途各站都按筛选后的范围计算。整趟路段由服务端一次返回，按天筛选在本地完成，**不产生额外的 `/public/routes` 请求**；行程视图不受筛选影响，始终按天展示整趟。
- 访客页右下角固定悬浮一个「看地图／看行程」按钮，与顶部的视图切换等价：长行程滚动到中段时也能一键切到地图或切回行程。它随页面滚动保持可见、在 390px 窄屏同样存在，位置按 `env(safe-area-inset-bottom)` 避开手机手势条，样式只引用 `--tf-*` 令牌并由样式契约测试守护。

因为两个视图都要展示站间距离，访客页拿到行程后**立即**向 `/public/routes` 算路，不再等访客切到地图视图；切换出行方式重算。整趟结果由服务端按分享与出行方式整体缓存，两个视图共用同一份结果，不产生额外上游请求。

### 6.2 访客 API 客户端

既有 `api` 是单例，中间件注入 Bearer 并在 401 时刷新会话后重放。访客页另建 `shareApi`：注入 `Authorization: Share <token>`，**不读 session store，401 不刷新、不重放**。令牌从 `route.params` 取，只放内存，不写 localStorage。

因为访客算路走 `/public/routes`（见 2.4），访客页**不需要**复用 `useItineraryRoutes`（它内部直接使用单例 `api` 调 geo），因此 `shared/api/geo.ts` 的三个函数签名原封不动，无需为分享改造。

### 6.3 复用与新增

复用：`AmapView.vue`（底图走 Caddy `/_AMapService` 代理，本就不校验登录）、`sortedItinerary`、`tripDays`、`formatDistance`、`formatDuration`、`--tf-*` 主题令牌。

新增目录 `src/share/`：`ShareLayout.vue`、`SharePage.vue`、`shareClient.ts`、`api.ts`。

主题：访客没有本地偏好，挂载时应用默认的有机自然主题。访客页样式只引用 `--tf-*` 令牌，由既有样式契约测试自动守护。

### 6.4 分享入口

旅行详情页顶部操作区新增分享按钮，沿用 T.12 确立的 Lucide 20px 图标与 `IconAction` 组件规范。

```
[未开启]  分享 ▸ 生成链接

[已开启]
https://…/s/9f3aK2mQx7
 复制   重新生成   关闭分享
```

「重新生成」与「关闭分享」需二次确认，文案说明旧链接会立即失效。

## 7. 边界与错误

### 7.1 访客侧

| 场景 | 行为 |
| --- | --- |
| 令牌不存在 / 已轮换 / 已关闭 | 404 SHARE_NOT_FOUND，页面显示「链接已失效」 |
| 旅行在回收站 | 410 TRIP_DELETED，页面显示「该旅行已被删除」 |
| 旅行已永久清理 | 分享行随 CASCADE 消失，等同令牌不存在，404 |
| 旅行已归档 | **正常可看**。归档是收纳，不是隐藏 |
| 主人账号处于 deleting | 403，页面显示「链接已失效」 |
| 算路配额耗尽或高德不可用 | `/public/routes` 503，两个视图都不显示站间距离：行程视图保留顺序与站点信息并标注「路线服务暂不可用」，地图视图降级为**示意连线**，明确标注不是道路距离，不显示总里程。按 2.4 的封闭接口约定，访客侧不提供重试按钮，刷新页面即重新请求 |
| 行程为空 | 正常渲染，显示空状态 |
| 全部行程点无坐标 | 行程视图正常，地图视图显示「本次行程还没有定位信息」 |

前端对以上失效状态统一呈现为友好页面，不暴露主人是否存在、旅行是否曾经存在等信息。

### 7.2 防收录与防滥用

- 后端对 `/public/*` 响应加 `X-Robots-Tag: noindex, nofollow`。
- 前端进入 `/s/:token` 时注入 `<meta name="robots" content="noindex">`。
- 令牌 128 位熵不可枚举；仍按客户端 IP 对 `/public/*` 整体限流，防止扫描式探测。
- `/public/*` 与站点同源，无需额外 CORS 配置。
