# Tripfolio 后台管理开发计划

更新时间：2026-10-01。以本版范围和[开发进度](./2026-10-01-后台管理开发进度.md)为后续开发依据。

## 1. 已确认范围

- 在现有仓库内保留独立 `apps/admin` 前端，共用 Go 后端和数据库。
- 后台只有超级管理员，首期由项目所有者使用；后续增加管理员时仍使用同一种身份。
- 仅密码登录，敏感操作再次输入密码，不使用验证器动态码。
- 最新调整：后台能了解一趟旅行的大概情况即可；不建设附件管理，也不查看逐条行程、物资、待办、成员或账目明细。
- 旅行概况保留名称、所属用户、目的地、日期、阶段、归档/回收站状态、预算、更新时间及内容数量。
- 私人概况访问仍须记录审计日志。已授权的账号管理和旅行层级管理继续按下列步骤开发。

本版替代原计划中的账单、附件查询/编辑及旅行内容明细管理。后台不新增笔记、预订、相册、会员收费、营销或多人协作功能。

## 2. 账号和权限

| 身份 | 权限 |
| --- | --- |
| 普通用户 | 使用原有用户端功能，不能访问后台 |
| 分享访客 | 按有效分享链接和限制状态访问，不获得后台权限 |
| 超级管理员 | 跨账号查看概况、管理用户和旅行、查看审计及运行状态 |

- 沿用现有账号，管理资格独立保存；注册和个人资料接口不能授予管理资格。
- 后台具有独立登录会话。用户端登录不代表已登录后台。
- 超级管理员资格通过受控 CLI 授予/撤销，首期不做角色配置或多人管理页面。
- 私人概况查询记录实际操作者、数据所属账号和对象编号；管理行为不会转移数据所有权。
- 每次请求检查最新资格、账号状态及会话；撤权后不能用旧会话继续访问。
- 不允许撤销、封禁或注销最后一个可用超级管理员。
- 不提供冒充用户登录、代用户修改密码、直接修改审计日志或执行服务器命令的入口。

## 3. 功能清单

| 模块 | 本期内容 |
| --- | --- |
| 平台概览 | 用户总量、今日新增、最近 7 天注册趋势、旅行总量、失败任务数量 |
| 用户管理 | 邮箱/昵称/账号编号/注册时间/状态筛选，基本资料、旅行数量、会话；后续封禁、解封、强制下线 |
| 旅行管理 | 按用户、名称、日期、阶段、归档和回收站状态筛选；查看单趟旅行概况 |
| 旅行概况 | 名称、用户、目的地、日期、状态、预算、更新时间；行程、物资、待办、成员各自数量 |
| 旅行操作 | 后续修改基础信息、归档、移入回收站、恢复和受控永久清理 |
| 分享限制 | 后续限制或解除旅行分享；管理限制独立于用户分享开关 |
| 审计中心 | 按操作者、对象所属账号、操作、时间、结果筛选访问和操作记录 |
| 运行状态 | 服务与依赖状态、失败任务、清理任务进度和脱敏错误摘要 |
| 账号与安全 | 管理身份、后台会话、退出当前或其他后台会话 |

不提供附件入口、预览或下载，也不展示文件数量和容量。旅行详情接口只返回概况白名单字段与数量，不返回私人备注、路线配置、明细数组或附件信息。

统计口径：平台“今日”按北京时间；旅行阶段按旅行自身时区；旅行总量包含归档但排除回收站；内容数量排除单独删除的记录；预算按旅行币种精度展示，不合并不同币种。

## 4. 审计与访问控制

- 登录成功/失败、退出、身份复验、权限拒绝、用户和旅行查询、管理操作、审计查询均留痕。
- 记录时间、操作者、对象所属账号、资源编号、操作、请求编号、来源信息和结果。
- 列表记录筛选范围、结果数量和对象编号；搜索内容使用摘要，不直接记录私人正文。
- 变更记录操作原因、字段及必要前后值摘要；不写入密码、验证码、会话令牌或分享令牌。
- 审计不可写时，私人概况访问和敏感操作必须失败。后台不提供审计记录修改、删除能力。
- 对象永久删除后保留审计标识，不级联删除操作历史。

## 5. 后续管理规则

### 用户和分享

封禁须填写原因，同时禁止登录、刷新、继续同步和分享访问，撤销旧会话并处理认证缓存。解封后要求重新登录，不恢复旧会话。最后一个可用超级管理员受保护。解除分享限制不会自动恢复旧链接，用户需要重新生成。

### 旅行基础信息与回收站

只管理旅行层级信息，不逐条编辑行程、物资、待办、成员、账目或附件。修改、归档、移入回收站和恢复均填写原因，检查版本冲突并更新用户端同步状态。

回收站以整趟旅行为单位，保留 30 天；恢复不得复活此前单独删除的记录，已申请永久清理的旅行不能恢复。

### 永久清理

后台仅超级管理员可申请或重试，需近期密码复验、原因及影响确认。先限制目标访问，再按现有数据关联规则执行真实清理；失败可见，重复操作不得扩大范围。只有全部清理完成才报告成功。

现有清理 worker 仍有占位逻辑，补齐之前不开放按钮。本期不增加全平台一键清空或新的自动永久清理规则。

## 6. 实施顺序与验收

按[开发进度](./2026-10-01-后台管理开发进度.md)逐项标记“未开始 / 正在开发 / 已完成”。当前先完成范围收缩与旅行概况，再做审计中心、运行状态、用户和旅行管理操作。

- 普通用户不能通过后台接口获取概况；撤权和会话过期立即生效。
- 超级管理员可以从用户定位旅行并查看概况，每次查询有审计。
- 页面和接口均不提供附件或逐条内容明细；旧后台明细路径不再可用。
- 内容数量不重复、不跨用户、不纳入单独删除记录；空旅行显示零。
- 封禁、分享限制、并发修改、恢复和永久清理分别通过实际场景验证后才标记完成。
- 后台构建并入原有发布流程，用户端功能不因后台范围调整而改动。
- 不以本地构建通过代替生产验证；生产账号授权和部署单独记录。

## 7. 参数

| 参数 | 当前约定 |
| --- | --- |
| 登录验证 | 密码登录；敏感操作再次验证密码 |
| 后台会话 | 最长 8 小时，闲置 30 分钟失效 |
| 密码复验有效期 | 5 分钟 |
| 审计保留期 | 180 天，后续维护策略单独实现 |
| 回收站保留期 | 30 天，不新增自动永久删除 |
| 用户通知 | 首期保留原因和审计，不增加邮件、推送或站内消息 |

实际生产账号提权由项目所有者指定账号后执行。
