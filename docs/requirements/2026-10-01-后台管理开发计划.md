# Tripfolio 后台管理开发计划

日期：2026-10-01

状态：已开始开发；执行步骤及接管记录见[后台管理开发进度](./2026-10-01-后台管理开发进度.md)。
范围：产品功能、账号权限、实施阶段和验收标准，不包含代码或数据库实现方案。

## 1. 已确认的方向

| 项目 | 约定 |
| --- | --- |
| 项目组织 | 沿用上一轮建议：同一仓库内增加独立后台前端，共用现有后端与数据库 |
| 首期使用者 | 由项目所有者本人使用，启用一个超级管理员；后台只设超级管理员一种管理身份 |
| 私人数据访问 | 超级管理员可以直接查看所有用户的私人旅行、账单和附件，不需要逐次获得用户授权；访问必须记录日志 |
| 内容修改 | 超级管理员可以修改用户内容，也可以将内容移入回收站 |
| 永久删除 | 后台永久删除权限仅属于超级管理员 |
| 当前交付 | 已获授权开始开发；按开发进度清单逐步实现并记录验证结果 |

“永久删除仅限超级管理员”约束后台操作。用户端对本人数据的既有删除规则单独保留，不因后台角色设计被扩大或取消。

## 2. 当前基础与需要补齐的能力

以下结论基于当前仓库检查，不能把历史需求文档中列出的功能全部视为已完成。

| 领域 | 当前基础 | 后台需要补齐 |
| --- | --- | --- |
| 账号 | 已有邮箱注册、登录、找回密码、个人资料、登录会话与撤销能力 | 超级管理员资格、后台会话、账号封禁、跨账号管理权限 |
| 账号状态 | 现有状态包含正常、注销中 | 增加封禁规则；不能把封禁错误显示成“账号正在注销” |
| 旅行内容 | 已有旅行、行程、物资、待办、成员、账单和分摊等业务模块 | 面向全平台的查询、查看、编辑和管理记录 |
| 旅行成员 | 表示同行人名称和费用分摊信息 | 不作为登录账号，也不作为后台权限角色 |
| 分享 | 已有只读分享、关闭分享、令牌轮换 | 超级管理员限制分享、限制原因和防止用户绕过限制的规则 |
| 文件 | 已有图片、PDF 等资产的上传、校验和下载授权 | 后台跨账号预览、下载审计、删除和恢复 |
| 回收站 | 已有旅行回收站及恢复规则，保留期为 30 天 | 账单、附件及本期允许删除的关联记录的恢复能力 |
| 永久清理 | 旅行永久清理任务当前仍为占位，会推迟执行 | 真正完成文件、业务记录及关联数据的清理，并反馈实际结果 |
| 运行状态 | 已有服务探针和后台任务框架 | 管理页面中的状态汇总、失败原因与清理进度 |

独立的笔记、预订、相册等完整管理页面，随对应用户端业务完成后再纳入，不根据已有表名推断功能已经可用。

## 3. 账号与权限体系

### 3.1 账号身份与管理资格

- 继续使用现有账号体系，后台管理资格附加到明确指定的账号上，不复制另一套个人账号资料。
- 普通注册只创建普通用户，不允许通过注册、修改个人资料或客户端提交身份字段获得超级管理员资格。
- 后台有独立登录入口和会话。用户端登录成功不等于已登录后台；后台会话与网页、Android 用户会话分别管理。
- 首个超级管理员通过受控初始化流程绑定到项目所有者确认的已验证账号，不能采用“第一个注册用户自动成为超级管理员”。
- 后台只保留超级管理员一种管理身份，不预留其他管理角色、角色分配或细粒度分权功能；首期只启用项目所有者的账号。
- 超级管理员资格与旅行所有权分别判断。超级管理员通过后台管理他人数据时，记录实际操作者和数据所属账号，数据所有权仍属于原用户。

### 3.2 身份划分

| 身份 | 数据范围 | 操作边界 | 首期安排 |
| --- | --- | --- | --- |
| 普通用户 | 本人的旅行与相关数据 | 现有用户端权限，不能进入后台 | 保持现有规则 |
| 分享访客 | 有效分享链接公开的内容 | 只读，不获得账号权限和后台权限 | 保持现有规则 |
| 超级管理员 | 全平台用户和私人业务详情 | 查看、下载、编辑、移入回收站、恢复、封禁普通用户、限制分享、永久清理及管理资格维护 | 首期启用，是唯一后台管理身份 |

账号身份仅区分普通用户与超级管理员，分享访客不属于账号角色。后续如需多人使用后台，也只增加权限相同的超级管理员账号，不引入分级管理。

### 3.3 超级管理员权限清单

后台操作统一要求有效的超级管理员资格和后台会话，敏感操作再执行身份复验及相应业务校验。

| 操作 | 规则 |
| --- | --- |
| 查看平台概览、账号列表与业务详情 | 允许，私人内容访问留痕 |
| 预览私人图片和 PDF | 允许，记录访问日志 |
| 主动下载私人附件 | 允许，记录下载日志 |
| 修改旅行、行程、账单等内容 | 允许，必须填写原因 |
| 移入回收站、在规则允许时恢复 | 允许，记录原因及关联影响 |
| 封禁普通用户、撤销普通用户会话 | 允许，记录操作原因 |
| 限制或解除限制分享 | 允许，记录操作原因 |
| 查看全平台后台审计记录 | 允许，查询行为同样留痕 |
| 后台永久清理及其人工重试 | 允许，需再次验证身份 |
| 授予或撤销他人的超级管理员资格 | 通过受控流程维护；首期不建设多人管理页面 |
| 修改或删除审计记录 | 后台不提供此能力 |

权限必须由后端执行，页面和按钮只负责展示。未列入允许范围的操作默认拒绝；新增功能必须先明确权限归属。

### 3.4 状态与会话规则

- 账号状态与管理资格分开：撤销管理资格只终止后台访问；封禁整个账号则限制用户端和后台访问。
- 封禁记录原因、操作者和时间；封禁后撤销已有会话，禁止登录、刷新、上传和新的私密文件访问授权，分享访问也受限。
- 解封后要求重新登录，不恢复旧会话。封禁不等同于注销，不自动删除用户内容。
- 后台退出、撤销超级管理员资格和封禁后，后续请求必须使用最新权限，覆盖现有认证缓存和已签发令牌的处理。
- 普通用户管理和个人资料入口不提供超级管理员资格编辑；资格授予与撤销通过单独的受控流程维护。
- 不允许通过撤权、封禁或注销操作移除最后一个可用超级管理员；需要保留受控的所有者恢复路径。
- 后台仅使用密码登录，不增加验证器动态码。超级管理员资格变更、永久删除等敏感操作通过再次输入密码完成近期身份复验。
- 已经下载的文件和 Android 离线缓存无法通过服务器封禁追溯收回；重新联网后的访问和同步按当前账号状态处理。

## 4. 首期功能清单

这里的“首期”指本次后台完整交付范围，不要求所有模块同时开发。

| 模块 | 首期功能 | 关键边界 |
| --- | --- | --- |
| 工作台 | 用户总量、今日新增、近期注册趋势、旅行数量、可用文件容量、失败任务概况 | 指标给出统计时间与口径，不将用户旅行消费当作平台收入 |
| 用户管理 | 按账号编号、邮箱、昵称、注册时间和状态检索；查看基本资料、最近访问、会话、旅行和文件数量；封禁、解封、强制下线 | 不显示密码、验证码、令牌；不代用户修改密码或转移账号所有权 |
| 旅行管理 | 按所属账号、名称、日期、阶段、归档状态检索；查看详情；修改基础信息；归档、移入回收站、恢复 | 区分计划中、进行中、已结束、归档、回收站等状态 |
| 行程与准备事项 | 在旅行详情内查看和编辑行程、路线相关业务字段、物资、待办、同行成员 | 复用已有业务约束；不把成员记录升级为多人协作账号 |
| 账单管理 | 查看支出、退款、分类、付款人、参与人、分摊和票据；修改账目；删除与恢复；查看旅行内统计 | 金额精度、退款上限、关联关系和分摊规则继续生效；不同币种分别汇总 |
| 文件管理 | 按用户、旅行、类型、处理状态筛选；查看文件大小和失败原因；预览、下载；修改允许的名称及关联信息；删除与恢复 | 私人文件每次访问留痕；不提供二进制文件内容编辑；不允许跨账号转移附件 |
| 分享管理 | 查看分享所属用户和旅行、开启状态、访问概况；限制分享、填写原因、解除限制 | 管理限制独立于用户分享开关；用户不能自行重开绕过限制；解除限制后由用户重新生成链接 |
| 统一回收站 | 按用户、对象类型、删除时间和操作者查询；查看删除原因及关联影响；恢复；超级管理员申请永久清理 | 包含旅行、账单、附件以及本期允许删除的关联记录 |
| 审计中心 | 查询后台登录、私人内容访问、修改、删除、恢复、封禁、下载和永久清理记录 | 按操作者、对象所属账号、操作、时间、结果筛选；敏感字段不进入日志正文 |
| 运行状态 | 查看服务及依赖状态、文件处理失败、路线任务失败、清理任务进度和最近错误摘要 | 普通运行任务首期以查看为主；不提供任意任务执行、数据库操作或服务器命令入口 |
| 我的后台账号 | 查看超级管理员身份、后台登录会话、安全设置；退出当前或其他后台会话 | 与用户端个人设置区分；不提供角色切换或权限配置 |

统计口径先统一为：平台“今日”使用北京时间；旅行总量统计未进入回收站的旅行，包含已归档旅行；文件容量表示系统记录的逻辑文件大小，不冒充对象存储账单。历史日活、留存和接口调用趋势需要另行采集数据，不从当前会话快照推算。

## 5. 私人数据访问与审计

### 5.1 哪些行为必须记录

- 后台登录成功或失败、退出、身份复验失败、越权请求。
- 用户检索、列表查询、打开私人旅行或账单详情、查看回收站内容。
- 图片和 PDF 预览、缩略图读取、主动下载，以及后续新增的导出操作。
- 内容修改、移入回收站、恢复、封禁、解封、撤销会话、限制分享。
- 管理资格变化、永久清理的申请、开始、完成、失败和人工重试。
- 审计中心自身的查询，记录查询人和查询范围，不递归记录日志写入动作。

列表查询记录筛选范围、结果数量和涉及的对象标识；批量读取不得只记“访问了某个页面”。搜索中的邮箱等字段以脱敏摘要表达。

### 5.2 每条记录包含什么

记录时间、实际操作者及当时的超级管理员资格、对象所属账号、资源类型和编号、操作类型、请求关联编号、来源信息、执行结果；修改类操作补充原因、变更字段和必要的前后值摘要。

不记录完整私人正文、附件内容、密码、验证码、会话令牌、分享令牌或可直接访问文件的签名链接。账号或业务对象永久删除后，保留必要的审计标识，不级联抹除操作历史。

### 5.3 如何保证记录可信

- 超级管理员的私人文件预览和下载通过受控入口逐次检查权限，记录传输开始、服务端完成或失败；不把“发出了下载授权”当作“用户已完成下载”。
- 审计记录不可写入时，私人数据访问和敏感变更不能继续成功执行；后台显示明确失败，运行日志保留故障信息。
- 管理动作与对应记录要保持一致，不能出现已修改却无审计记录，或操作失败却记为成功。
- 应用后台不允许修改或删除历史审计记录；保留期满后的归档与清理通过单独的维护规则执行。

## 6. 编辑、回收站和永久清理规则

### 6.1 编辑

- 超级管理员的所有修改必须填写操作原因，并明确展示正在操作哪个用户的内容。
- 保留原有金额、退款、分摊、旅行归属和文件引用校验，不因超级管理员身份跳过业务规则。
- 超级管理员和用户同时修改时提示冲突，不覆盖对方的新版本。
- 变更进入原用户的数据更新链路，相关统计和路线按需要更新；用户重新读取或同步时获得正确结果。
- 首期操作已有内容，不增加“冒充用户登录”功能。

### 6.2 删除和恢复

- 常规删除先进入回收站；确认时展示目标与关联影响，日志记录实际删除人及原因。
- 删除整趟旅行后，其分享及相关内容访问同时受限。恢复旅行只恢复此次删除影响的内容，不能复活此前单独删除的账单或附件。
- 恢复单条内容前检查所属旅行、分类、成员及引用关系；父级仍在回收站时应先恢复父级。
- 账单与关联退款、分摊、附件的删除和恢复必须保证一致，不能留下孤立记录或错误统计。
- 删除被多处引用的附件前列出引用，按关联规则处理；不能直接删掉仍被有效内容使用的文件。
- 沿用旅行回收站的 30 天规则作为首期建议；已申请永久清理的对象不能再次恢复。其他对象保留期建议统一，见文末。

### 6.3 永久清理

- 后台仅超级管理员可发起，必须再次验证身份、填写原因、确认目标和影响范围。
- 首期逐项或按单趟旅行处理，不开放全平台一键清空和批量永久删除。
- 清理任务先限制目标访问，再完成关联数据和实际文件清理；同一任务重复提交或重试不能重复执行破坏性操作。
- 提供待执行、执行中、成功、失败等真实状态；失败时保留可定位的原因和已完成阶段。
- 只有实际清理完成才能显示“永久删除成功”。文件删除失败、任务被推迟或只完成部分数据库更新都不能计为成功。
- 永久清理的后台申请和人工重试入口均须检查有效的超级管理员资格。后台新增的自动清理规则不在首期范围内。
- 永久清理后保留必要的审计信息；备份中的历史副本按备份保留策略到期处理，不能承诺立即从所有备份中消失。

## 7. 后续功能范围

下列能力预留方向，本次不与首期捆绑开发。

| 方向 | 后续内容 | 启动条件 |
| --- | --- | --- |
| 超级管理员维护 | 添加或撤销超级管理员资格、交接管理资格；所有超级管理员权限相同 | 实际需要多人共同管理或交接 |
| 运营配置 | 公告、注册开关、默认物资库、公共模板和配额管理 | 明确需要后台动态维护的配置项 |
| 运营分析 | 日活、留存、功能使用、地图调用与失败趋势 | 先补齐采集口径和历史数据 |
| 数据导出 | 管理报表、受控业务导出、导出任务与下载审计 | 明确导出字段、范围和用途 |
| 运行维护 | 安全的文件校验和路线任务重试、失败提醒 | 首期状态观察稳定且重试规则明确 |
| 账号生命周期 | 完整账号注销、个人数据导出、申诉与处理流程 | 与用户端的数据管理需求一起确定 |
| 新业务管理 | 完整笔记、预订、相册等管理能力 | 对应用户端功能已经可用 |

会员等级、订阅收费、订单支付、营销推送、多租户和多人协作旅行不纳入本次后台计划。

## 8. 开发阶段与交付标准

按依赖顺序推进，不依据尚未确定的人员投入承诺具体自然日工期。

| 阶段 | 工作内容 | 阶段交付与通过条件 |
| --- | --- | --- |
| 1. 确定规则 | 固定首期功能、超级管理员权限清单、账号状态、审计范围、删除与恢复规则；确认文末参数 | 范围无歧义，涉及未完成业务的补齐工作单独列出 |
| 2. 管理基础 | 独立后台入口、初始超级管理员、后台登录和会话、权限校验、审计基础、后台布局 | 普通账号无法访问任何管理接口；管理访问可追踪；撤权有效 |
| 3. 查询与工作台 | 用户查询、旅行及内容详情、账单详情、文件预览下载、平台概览、审计查询和运行状态 | 可以从用户定位到旅行、账单、附件及对应访问记录；统计口径正确 |
| 4. 管理操作 | 用户封禁与解封、强制下线、分享限制、内容编辑、移入回收站与恢复 | 所有后台动作验证超级管理员资格，有原因、有记录，用户端数据保持一致 |
| 5. 永久清理 | 补齐真实清理能力、超级管理员复验、影响预览、进度、失败处理和受控重试 | 数据与文件真实清理，失败可见；没有超级管理员资格的账号无法通过后台发起或重试 |
| 6. 联调与发布 | 后台访问边界、并发操作、撤权、审计失败、恢复冲突、清理失败验证；沿用现有部署形式发布 | 关键验收全部通过；生产环境只授予指定账号后台资格 |

后台页面和权限基础可逐步交付，但审计完成前不开放私人内容访问，真实清理完成前不开放永久删除。

### 首期最终验收场景

1. 普通用户直接访问后台页面、管理接口或猜测对象编号，都不能获取他人数据。
2. 超级管理员能跨账号定位旅行、账单和附件，列表、详情、预览与下载均有对应记录。
3. 后台仅使用超级管理员身份；普通用户管理和个人资料入口无法授予或修改超级管理员资格。
4. 封禁后网页、Android、后台和分享入口遵循统一限制；已有会话和缓存不能继续放行新请求。
5. 管理资格撤销后后台访问失效，普通账号资格按自身状态保留；最后一个超级管理员受到保护。
6. 用户与超级管理员同时编辑产生明确冲突，统计、路线及数据更新链路没有漏更新。
7. 删除和恢复关联账目、退款、分摊及附件不会造成错账、孤立关系或此前已删除内容意外复活。
8. 审计故障时私人内容访问和敏感修改失败，日志不泄漏凭证或私人正文。
9. 分享被管理限制后用户不能自行重开，解除限制不会自动复活旧链接。
10. 永久清理失败不会显示成功，重试不会越权或扩大删除范围，仍被有效内容引用的文件不会误删。
11. 全平台统计区分回收站与归档，不把多币种金额直接相加，也不虚构历史活跃数据。
12. 后台加入现有发布流程后，用户端登录、旅行编辑、分享和文件访问仍能正常工作。

## 9. 开发参数

密码登录已由用户确认；其余参数在开始开发时按下列建议值实施，有调整时同步修改本表与进度记录。

| 事项 | 建议 | 对范围的影响 |
| --- | --- | --- |
| 后台登录验证 | 仅使用密码，不引入验证器动态码；敏感操作再次验证密码 | 复用现有账号密码，后台会话独立 |
| 后台会话时长 | 闲置 30 分钟退出，单次登录最长 8 小时；敏感操作使用 5 分钟内身份复验 | 决定会话管理和重新登录体验 |
| 审计保留期 | 先保留 180 天，可按实际日志量再调整归档策略 | 影响存储、检索和到期维护成本 |
| 回收站保留期 | 旅行沿用现有 30 天，新增的账单和附件回收站也采用 30 天 | 决定恢复期限和清理提示，不擅自增加自动永久删除 |
| 用户侧变更通知 | 首期后台保留修改原因和审计，暂不增加邮件、推送或站内消息 | 若需要主动告知用户，须增加通知渠道和消息展示 |

账号初始化只提供受控入口；实际授予哪个现有账号超级管理员资格，由项目所有者指定。
