# Tripfolio 功能清单 v0.1

日期：2026-09-10  
状态：需求讨论稿；目标用户已确认，功能边界与优先级为建议。  
目标用户：面向大众的个人旅行用户。  
使用平台：安卓移动端、网页端。

## 1. 产品定位

围绕“一次旅行”，把行前规划与准备、途中行程与开支记录、旅后回顾与资料归档连接起来，形成个人可以长期保存的旅行档案。

核心流程：创建旅行 → 编排路书与预算 → 完成准备清单 → 途中查看与记录 → 旅后回顾与归档。

“路书”建议先定义为按天组织的行程，包含地点、时间、交通、住宿和注意事项；自驾专属的里程、补能和道路信息作为扩展。旅行中可以记录同行人备注，首版数据仍由旅行创建者个人管理。

### 可选切入方式

| 方向 | 主要价值 | 取舍 |
| --- | --- | --- |
| 个人旅行全流程工具（推荐） | 同一趟旅行内连接路书、准备、开支和记录，覆盖用户提出的主要需求 | 需要控制每个模块的深度，先完成基础流程 |
| 路书与准备优先 | 提前规划、整理预订和查阅资料的体验更集中 | 记账分析和旅后回顾需要后续补充 |
| 记账与旅行回忆优先 | 适合旅途中随手记录，形成长期个人档案 | 行前规划和复杂路线编排相对较弱 |

建议采用第一个方向，首版完成基础流程，后续根据实际使用频率加深各模块。

## 2. 优先级定义

- **P0：首版核心。** 可以独立完成一次旅行的规划、准备、记录和回看。
- **P1：体验增强。** 提高复用效率，丰富旅行方式和记录表达。
- **P2：后续探索。** 需要多人协作、外部数据、智能能力或专业旅行场景支持。

优先级表达建议的版本范围，不代表已经确定的开发排期。

## 3. P0：首版核心功能

| 编号 | 模块 | 功能清单 | 首版边界与关键规则 |
| --- | --- | --- | --- |
| F01 | 账号与个人空间 | 注册、登录、退出、账号找回；个人资料；同一账号在安卓和网页访问旅行数据 | 旅行、照片、账单和附件默认仅本人可见；支持注销账号与删除个人数据 |
| F02 | 旅行管理 | 创建、编辑、归档、删除旅行；设置名称、起止日期、目的地和备注；区分计划中、进行中、已结束；按名称或目的地查找 | 一次旅行是路书、准备事项、开支和记录的共同归属；允许旅行结束后补记和修正 |
| F03 | 每日路书 | 按天添加景点、交通、住宿、餐饮和其他活动；记录时间、地点、地址、预计停留时长及备注；调整顺序、移动到其他日期 | 活动时间可以留空；支持跨日交通、住宿；同一活动可关联预订资料和开支 |
| F04 | 途中行程查看 | 查看今日安排和整趟行程；活动标记为已完成、跳过；填写实际发生情况；从地点打开地图导航 | 行程有变时保留原计划与实际记录的区分；首版提供地址录入、地点选择和外部地图导航 |
| F05 | 物资清单 | 按证件、衣物、洗漱、电子设备、药品等分类；增删物品；设置数量与备注；提供基础旅行模板 | 物品状态区分“待准备、已备齐、已装包”；新旅行从模板创建独立清单，避免复用上次勾选状态 |
| F06 | 行前待办 | 记录订票、订酒店、办理证件、购买保险等准备事项；设置截止日期、完成状态；查看逾期和未完成项 | 待办表达要完成的事情，物资清单表达要携带的东西；可以在旅行中分别查看进度 |
| F07 | 预算管理 | 设置旅行总预算和可选的分类预算；查看已支出和剩余预算；标识超预算 | 路书中的预计费用属于计划，不直接计入实际支出；每趟旅行先使用一种记账币种 |
| F08 | 旅行记账 | 快速新增、编辑、删除开支；填写金额、分类、日期和备注；记录退款；可关联具体活动和票据 | 金额和分类为主要输入；日期默认当天、旅行默认当前旅行；退款冲减支出；交通、住宿、餐饮、门票、购物和其他为基础分类 |
| F09 | 开支统计 | 查看总支出、每日支出、分类占比、预算与实际对比；筛选明细 | 统计口径以实际开支减退款为准；首版围绕个人账本组织 |
| F10 | 预订与资料 | 手动记录车次或航班、出发到达时间、酒店入住退房、预约项目、地址、联系电话和订单备注；添加图片、PDF 附件 | 预订可关联路书；可以只保存需要的信息；票据与证件类资料保持私密 |
| F11 | 旅行笔记与照片 | 给整趟旅行或某一天写笔记、上传照片、添加说明；按天回看行程、笔记、照片和开支 | 支持途中简记和结束后补充；照片位置由用户选择是否使用；首版提供基础展示与浏览 |
| F12 | 安卓离线与跨端同步 | 将指定旅行的路书、清单、账本、文字笔记和选定重要附件保存到本地；离线查看；离线记账、写文字笔记、勾选清单；联网后同步 | 显示离线资料是否准备完成、待同步或同步失败状态；网页首版以在线使用为主；离线地图和未下载附件另行规划；冲突时保留冲突内容并提示处理，避免静默丢失修改 |
| F13 | 数据导出与误删保护 | 下载个人旅行数据、照片和附件；导出开支 CSV；旅行删除前确认；提供回收站恢复 | 导出覆盖用户保存的内容；回收站建议保留 30 天；账号注销的删除流程单独说明 |

## 6. 安卓端与网页端的分工

两端使用同一份旅行数据，基础功能保持互通，操作侧重点可以不同。

| 场景 | 安卓端重点 | 网页端重点 |
| --- | --- | --- |
| 创建与整理旅行 | 随时新建、修改当前行程 | 集中整理多天行程、长备注和资料 |
| 路书 | 今日安排、地址导航、途中调整 | 多日编排、地点对照、批量整理 |
| 准备清单 | 收拾行李时勾选、随时补充 | 编辑分类、数量、模板 |
| 开支 | 快速记账、拍摄票据 | 查账、修改明细、预算分析、导出 |
| 笔记与照片 | 随手记录、从相机或相册添加 | 整理文字、照片、旅后回顾 |
| 网络不稳定 | 首版支持已下载资料及指定操作离线使用 | 首版在线使用；网页离线能力后续评估 |
| 提醒 | P1 系统提醒 | P1 站内提醒 |

首版两端均支持基础路书编辑、清单管理、记账和资料查看。

## 7. 模块之间的关联规则

1. **以旅行为中心。** 路书、物资、待办、账本、资料、照片与笔记属于同一趟旅行，支持按天聚合查看。
2. **活动可以串联信息。** 例如一条“入住酒店”活动，可关联预订信息、酒店地址、付款记录和入住前待办；后续再关联提醒。
3. **计划和实际分别保留。** 预计住宿费 800 元，实际支付 760 元，统计实际支出为 760 元；跳过景点时，已发生的不可退门票支出继续保留。
4. **预付款可以早于出发日期。** 旅行开始前购买的机票归入该旅行，记账日期保持真实付款日期；旅行统计包含这笔支出。
5. **资料与账单按需关联。** 上传一张票据不会自动产生第二笔开支；删除路书活动时，已有账单和笔记仍然保留，只解除关联。
6. **归档后仍能补充。** 用户可以在回家后补记开支、整理照片、修改说明，统计同步更新。
7. **同步状态清晰。** 本地待上传记录、同步失败和版本冲突均应可见；断网不会使已保存的记录消失。
8. **公开与分享由用户主动选择。** 私密是默认状态，分享范围、时效和撤销入口应明确。

## 8. 首版使用流程与验收场景

以“一次 5 天旅行”为例，首版至少能够完成以下流程：

1. 用户在网页创建旅行，填写日期、目的地和总预算，安排 5 天行程，保存交通与酒店资料。
2. 从基础物资模板生成本次清单，补充需要购买的物品和需要提前办理的待办。
3. 在安卓登录后看到相同数据，将本次旅行和重要预订附件保存供离线使用，并能看到下载是否完成。
4. 旅途中查看当天安排、打开地图导航、勾选已装包物品和已完成活动，新增开支、退款、文字笔记和照片。
5. 断网时仍能查看已下载资料、记录开支与文字笔记、更新清单；联网后修改同步到网页，冲突记录可处理。
6. 旅行结束后，用户查看每日与分类支出、预算差额、笔记和照片，补齐记录并归档。
7. 用户能够下载旅行数据与开支明细，并恢复回收站内误删的旅行；其他用户不能访问未分享的内容。

体验目标：常用记录入口容易找到；新增一笔普通开支主要填写金额和分类；当前旅行、当天日期等能够合理默认，其他信息可后补。

## 9. 后续需求细化重点

以下事项会影响具体设计，当前清单将相关能力分层列出，供下一轮逐项细化：

- **路书的主要使用方式：** 日程安排、自驾路线、多城市交通之间的侧重点，以及地图总览是否需要提前进入首版。
- **首发旅行场景：** 境内游与境外游的占比，决定多币种、时区、地图和天气服务的优先级。
- **记录的侧重点：** 实用资料与开支整理、照片和旅行回忆之间的权重，决定首页及旅行详情的信息排序。
- **账号与容量安排：** 登录方式、照片和附件容量、游客试用，以及是否引入付费服务。

建议下一轮先细化 F03–F04 的路书结构，再确定 P0 的具体页面、字段和操作流程。
