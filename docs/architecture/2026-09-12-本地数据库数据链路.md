# 本地数据库数据链路（SQLite spike）

日期：2026-09-12  
状态：本机验证通过（Node 内置 sqlite 驱动同一套代码），真机验证待用户在安卓设备上执行。  
依据：技术选型 v0.4 第 4.3、7.1、10 节；接口设计 4.1（待同步操作载荷）。

## 1. 结构

```text
apps/client/src/platform/localdb/
  executor.ts      SqlExecutor / SqlConnection / SqlConnectionOpener 接口；业务代码只依赖这里
  names.ts         每账号一个数据库：tripfolio-<账号ID>
  schema.ts        v1 表结构：kv、trips、expense_categories、ledger_entries、pending_operations
  migrations.ts    自管理的版本化迁移（local_migrations 表），每个版本一个事务
  database.ts      LocalDatabase：打开即迁移；离线记账把业务行与待同步操作放同一事务
  selfcheck.ts     自检场景：单元测试与真机自检页共用
  node/nodeSqlite.ts   Node 内置 sqlite 实现，只供单元测试
apps/client/src/platform/capacitor/localDatabase.ts   @capacitor-community/sqlite 8.1.1 实现（安卓）
apps/client/src/mobile/pages/DevLocalDbPage.vue       真机自检页（路由 /dev/local-db，移动壳可见）
```

平台接口只有三种操作（exec、run、query）加事务与关闭，足够承载迁移、仓储与同步逻辑；鸿蒙阶段只需再写一个实现。

## 2. 已核对的插件行为（8.1.1 安卓源码）

- 打开数据库时插件已执行 `setForeignKeyConstraintsEnabled(true)`，外键约束默认生效。
- `run`、`execute`、`executeSet` 的 `transaction` 参数为 true 时插件自行开关事务；我们用 `beginTransaction` / `commitTransaction` / `rollbackTransaction` 管理事务，事务内一律传 `transaction=false`，否则报 "Already in transaction"。
- `createConnection` 对同名已存在的连接抛错，因此先 `isConnection` 再 `retrieveConnection`；页面重载后先 `checkConnectionsConsistency` 与原生侧对齐。
- 数据库文件名为 `<名称>SQLite.db`，位于应用私有目录；`isDatabase` 判断文件是否存在不需要连接，`deleteDatabase` 需要先有连接。
- 不加密（`androidIsEncryption: false`）：数据是用户自己的旅行数据，凭证另存安全存储。

## 3. 自检场景（selfcheck.ts）

| 步骤 | 验证内容 | 对应验证项 |
| --- | --- | --- |
| 1 | 打开账号 A 的数据库，迁移到最新结构版本 | 迁移 |
| 2 | 同一事务写入旅行、分类、账目与 `ledger_entry.create` 待同步操作，账目标记为待同步 | 事务、待同步操作 |
| 3 | 事务中途抛错，账目数不变 | 事务回滚 |
| 4 | 引用不存在旅行的账目被外键拒绝，且不留下待同步操作 | 约束、事务原子性 |
| 5 | 关闭后重开：数据保留，迁移不重复 | 应用重启后的数据保留 |
| 6 | 账号 B 的数据库为空且名称不同，账号 A 数据不受影响 | 按账号隔离 |
| 7 | 删除账号 B 的数据库后文件不存在 | 清理本地缓存 |

另有“本页打开次数”计数：每次进入自检页加一并持久化，用于验证完全退出应用后的保留。

本机结果：`pnpm --filter @tripfolio/client test` 中 10 个本地数据库用例全部通过（含迁移升级、失败回滚、版本高于程序时拒绝打开、旧版本不覆盖新版本）。

## 4. 真机验证步骤

前置：JDK 21、Android SDK、一台开启 USB 调试的安卓手机（或模拟器）。

```bash
pnpm --filter @tripfolio/client build
pnpm --filter @tripfolio/client cap:sync
pnpm --filter @tripfolio/client cap:open      # Android Studio 中 Run
```

1. 应用启动后进入“旅行”页，点开“开发工具 → 本地数据库自检”，点“运行自检”，7 个步骤应全部显示“通过”。
2. 记下“本页打开次数”，从最近任务里划掉应用（完全退出），重新打开并进入本页，计数应加一。
3. 在系统设置里查看应用存储占用，删除账号 B 数据库后不应残留 `tripfolio-selfcheck-bSQLite.db`（可用 Android Studio 的 Device Explorer 查看 `/data/data/com.tripfolio.app/databases/`）。

任一步失败时记录步骤名与 detail 文本，插件侧问题优先核对第 2 节的事务参数与连接名处理。

## 6. 安卓工程调整（已落入 android/）

- `AndroidManifest.xml`：`allowBackup="false"`、`fullBackupContent="false"`、`dataExtractionRules="@xml/data_extraction_rules"`。
- `res/xml/data_extraction_rules.xml`：云备份与设备迁移都排除 database、sharedpref、root、external。理由：恢复旧数据库会与账号的同步游标、待同步操作和已删除记录冲突，凭证也不应离开 Keystore 所在设备；数据由服务端与同步机制重建。
- 插件 README 要求 JDK 21、minSdk 23+；Capacitor 8 生成的工程为 minSdk 24、compile/target 36，满足要求。
