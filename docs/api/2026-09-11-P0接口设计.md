## 1. 公共协议

### 1.1 路径、身份与权限

- 以下业务路径统一加前缀 /api/v1。JSON 使用 snake_case；路径 ID 使用 UUID，生成式 operationId 见接口清单。
- 除 metadata、注册、登录、验证码、找回和刷新入口外，接口要求有效身份。内置物品库需登录。账号 ID 只从认证上下文取得，不接受请求指定所属账号。
- 默认 Authorization: Bearer <access_token>。任意旅行子资源必须同时验证当前账号、路径 trip_id 与目标资源；跨账号/跨旅行 ID 返回 404，不暴露其存在性。
- 访客分享路径 /public/* 使用 Authorization: Share <token>，不要求账号身份、也不接受账号身份代替；令牌只能读取它所属那一趟旅行的公开模型（2.11、3.11），主人注销中返回 403 ACCOUNT_DELETING，旅行在回收站返回 410 TRIP_DELETED。
- 单资源 GET 返回 data 包装及 ETag；列表返回 items 和 next_cursor。request_id 放 X-Request-ID 响应头，不插入规范资源正文。
- 列表可带随时间变化的阶段/逾期等展示信息；规范单资源不含这些派生内容或临时下载 URL，使资源版本可作为稳定 ETag。
- 账户为 deleting 时，仅允许当前有效会话补领注销查询凭证、重试已成功的同一注销请求和退出，或使用注销只读凭证查询进度；普通旅行读写、下载、新登录和刷新均拒绝。
- 普通业务路径命中本人的回收站旅行返回 410 TRIP_DELETED（读写一致）；单项已删除或已永久清理的资源返回 410 RESOURCE_GONE。不存在或非本人资源仍返回 404 RESOURCE_NOT_FOUND。

### 1.2 幂等、版本与 PATCH

- 除单独说明的认证/会话/临时授权接口外，业务写请求必须带 Idempotency-Key: <UUID>。相同成功操作重试复用同一键，用户改变内容则生成新键。
- 创建普通业务资源时客户端提供 id；服务端任务 ID 可由服务端生成。创建不带 If-Match，仍需验证 ID 未被使用。
- 修改、删除或对已有资源执行动作时，带 If-Match: "<version>"；例如 "7"。不接受 * 或弱 ETag。缺少返回 428。If-Match 表示客户端所基于的版本：DELETE、动作接口（archive、restore、purge、账号注销）和 PUT 整体替换要求版本相等，不符返回 412 VERSION_CONFLICT；PATCH 允许基线落后，服务端读取基线之后各版本的 changed_fields 并求并集，与本次提交字段不相交时合并应用（版本递增，warnings 含 MERGED_WITH_NEWER_VERSION），相交、所需变更日志已过期或目标已删除时返回 412，conflict 中附 conflicting_fields。
- 重排使用请求中的各行 base_version，不用单一 If-Match；模板追加、快照/导出任务创建使用自身幂等键；资产上传确认以尝试序号 upload_attempt 标识当前尝试，不使用 If-Match。
- PATCH 使用 application/json 的明确字段模型：缺省字段保持原值；可空字段显式 null 表示清空；数组出现时整体替换；不可空字段传 null 或写入只读字段返回 422。
- 不使用通用任意字段更新器，也不接收客户端提供的 version、created_at、account_id 或对象存储键。
- 服务端先检查成功操作收据，再处理其旧版本条件。REST 与 sync/push 的同一业务命令使用一致的规范化指纹：指纹 = SHA-256(operation_type ‖ 目标标识 ‖ 基线版本 ‖ 规范化命令)，命令为解析并校验后的内部结构体按固定字段顺序的确定性编码；Money 按币种小数位规范化（"128.5" 与 "128.50" 相同）；缺省字段与显式 null 区分；文本不做 Unicode 归一化；不包含路径形式、认证令牌、request_id 或其他请求头。同一 operation_id 携带不同指纹返回 409 IDEMPOTENCY_CONFLICT。
- 写操作统一返回 WriteResult，其 data 字段为 primary 资源的当前规范表示（含服务端写入的默认值、sort_order、completed_at 等），调用方无需再次 GET。收据不保留业务正文；重放时服务端按 primary 的 ID 重新读取当前资源填充 data，目标已永久清理时 data 为 null。

### 1.3 基础类型与分页

| 类型 | 约定 |
| --- | --- |
| UUID | 标准 UUID 字符串；客户端优先 UUIDv7，兼容 UUIDv4，不按 ID 推断同步顺序 |
| Version | 正整数十进制字符串，例如 "7" |
| Money | 非科学计数法的十进制字符串；存储上限 NUMERIC(18,4)，按币种校验小数位 |
| Date | YYYY-MM-DD，不带时区 |
| LocalDateTime | YYYY-MM-DDTHH:mm:ss，不带 Z 或偏移，按旅行 timezone 解释；OpenAPI 用 pattern，不误标为 RFC 3339 date-time |
| Instant | RFC 3339 UTC，例如 2026-09-11T08:30:00Z |
| Currency | 支持清单内的 ISO 4217 三字母大写代码 |
| Sha256 | 64 位小写十六进制字符串 |
| PageQuery | limit 默认 50，范围 1–100；cursor 可省略，只接受服务端生成值 |
| Page<T> | items: T[]、next_cursor: string 或 null；不默认返回昂贵的 total_count |

普通列表使用固定排序的键集分页，游标绑定账号、路径、筛选与排序；改变筛选需重新开始。列表在并发修改时可能变化，不提供快照承诺；离线初始化和导出使用专门快照。

正文默认最多 1 MiB；单个同步操作最多 64 KiB，单次最多 100 个操作且合计不超过 1 MiB。所有文本使用有效 UTF-8，具体长度见模型与表结构；未知 JSON 字段被拒绝。

### 1.4 响应模型

WriteResult：

```json
{
  "operation_id": "019ed632-51c0-7000-8000-000000000001",
  "primary": {
    "type": "ledger_entry",
    "id": "019ed632-51c0-7000-8000-000000000002",
    "version": "1"
  },
  "affected": [
    {
      "type": "ledger_entry",
      "id": "019ed632-51c0-7000-8000-000000000002",
      "version": "1"
    }
  ],
  "commit_cursor": "opaque-account-cursor",
  "warnings": [],
  "replayed": false,
  "data": {
    "id": "019ed632-51c0-7000-8000-000000000002",
    "trip_id": "019ed632-51c0-7000-8000-000000000004",
    "kind": "expense",
    "amount": "128.50",
    "currency_code": "CNY",
    "category_id": "019ed632-51c0-7000-8000-000000000005",
    "occurred_on": "2026-09-11",
    "notes": "午餐",
    "refunded_entry_id": null,
    "attachment_asset_ids": [],
    "version": "1",
    "created_at": "2026-09-11T04:30:00Z",
    "updated_at": "2026-09-11T04:30:00Z",
    "deleted_at": null
  }
}
```

- affected 包含本操作全部变化资源，含 primary；任务等没有资源版本时 version=null。data 为 primary 的规范资源（任务类接口为任务资源）；replayed=true 时按 ID 重新读取当前态，目标已永久清理则为 null。
- 无旅行同步变更时 commit_cursor=null。commit_cursor 只是本次提交标识，客户端不得用它跳过尚未拉取的其他变更；同步进度只能由完整消费的 next_cursor 或完成的 baseline 推进。
- warnings 仅为稳定的代码与字段路径，不缓存业务正文。警告代码清单：ITINERARY_OUTSIDE_TRIP_DATES、TIMEZONE_INTERPRETATION_CHANGED、MERGED_WITH_NEWER_VERSION、REFUNDS_UNLINKED。
- 初次创建返回 201，后台请求返回 202，更新/删除返回 200；成功重试返回同类成功状态并令 replayed=true。认证和明确的临时授权响应另有专用模型。
- 普通单资源响应为 {"data": resource}，写响应为 {"data": WriteResult}，列表直接使用 Page<T>。下文示例省略外层 data。

错误使用 application/problem+json：

```json
{
  "type": "about:blank",
  "title": "资源已被修改",
  "status": 412,
  "code": "VERSION_CONFLICT",
  "detail": "请核对另一端的修改后重试。",
  "request_id": "req_...",
  "conflict": {
    "entity_type": "ledger_entry",
    "entity_id": "019ed632-51c0-7000-8000-000000000002",
    "expected_version": "1",
    "current_version": "2",
    "conflicting_fields": ["amount"],
    "current": {}
  }
}
```

current 在实际响应中是经过权限和白名单校验的完整当前资源；conflicting_fields 列出本次提交中与基线之后变更相交的字段，因日志过期无法判断时为 null。删除冲突则返回 deletion_context，不伪造可编辑的 current。校验错误提供 errors:[{field,code,message}]。

## 3. 请求与资源字段

下面用 * 标记创建时必填字段。没有 * 的创建字段使用列出的默认值；PATCH 只允许对应说明中的可写字段。所有长度、数字边界、枚举和关联约束同时遵循数据库字段字典。类型与列不同的地方在本节明确转换，不能把数据库行直接序列化为响应。

### 3.1 认证与账户

| 模型 | 字段 |
| --- | --- |
| EmailChallengeRequest | purpose*: register/reset_password；email*: string |
| EmailChallengeResult | challenge_id、expires_in_seconds=600、retry_after_seconds=60；不返回验证码或账号是否存在 |
| RegisterRequest | challenge_id*、email*、code*、password*、nickname*、client*: ClientInfo |
| LoginRequest | email*、password*、client*: ClientInfo |
| ClientInfo | kind*: web/android/harmony；device_id*: UUID；device_name?: string，最多 120 字符 |
| RefreshRequest | 网页端使用 Cookie，正文为空；原生端正文 refresh_token*: string |
| ResetPasswordRequest | challenge_id*、email*、code*、new_password* |
| ReauthenticateRequest | password* |
| AuthResult | access_token、token_type="Bearer"、expires_in_seconds=900、account；原生端另含 refresh_token，网页端通过 HttpOnly Cookie 设置并返回 csrf_token |

| Account | id、email、nickname、avatar_asset_id、default_timezone、status、version、created_at、updated_at |

邮箱长度最多 254，规范化规则见 accounts。密码 8–128 个 Unicode 字符，不裁剪空格、不自动 Unicode 归一化，不强制某类字符组合（字母、数字、符号与中文都可以）；服务端限制输入字节总长。**登录与密码复验只校验上限，不校验下限**，避免老密码被挡在门外。验证码为 6 位十进制字符串，保留前导零。

验证码请求、错误登录和密码找回采用统一外部错误，不在验证邮箱归属前暴露账号是否存在。验证码挑战的生成、限流和投递不依赖邮箱是否已有账号；验证成功后，注册可返回 ACCOUNT_ALREADY_EXISTS，找回不存在账号仍返回通用结果。

访问 JWT 有效期 15 分钟，含 sub、sid、iss、aud、iat、exp；每次请求核对会话与账号状态，结果按会话在进程内缓存 60 秒（登出、撤销、改密、重新认证即时失效，跨设备撤销最多延迟 60 秒生效）。refresh token 形如 `<session_id>.<secret>`，secret 为至少 256 位随机值的 base64url 编码，网页 Cookie 值即完整字符串；绝对有效期 30 天，每次刷新轮换。服务端按 session_id 定位会话行并加锁，对 secret 的 SHA-256 与当前摘要、前次摘要做常量时间比较：命中当前摘要即轮换（前次摘要 ← 当前摘要，记录轮换时间）；命中前次摘要且距上次轮换不超过 60 秒，视为响应丢失后的重试，签发新的令牌对并只替换当前摘要，前次摘要与轮换时间保持不变；命中前次摘要但超出宽限期视为令牌复用，撤销该会话；其他情况仅拒绝，不撤销任何会话。网页端用 Web Locks API（navigator.locks）跨标签页串行刷新，原生端进程内串行；刷新请求不需要幂等键，可原样重发。重置密码撤销全部会话，需重新登录。

网页端刷新凭证使用 Secure、HttpOnly、SameSite=Lax 的 __Host-tripfolio_refresh Cookie，Path=/，不设置 Domain；access_token 只放内存。使用 Cookie 的刷新、退出等请求必须校验同源 Origin，以及 X-CSRF-Token 请求头。CSRF token 为登录/刷新时签发的随机值，以 csrf_token 字段和非 HttpOnly 的 __Host-tripfolio_csrf Cookie 返回；该 Cookie 同样 Secure、SameSite=Lax、Path=/、无 Domain。请求头必须与 Cookie 值相同，其摘要还必须匹配 account_sessions.csrf_token_hash。任何 Cookie 凭证请求均执行此校验，不因 client.kind 改为 android 而跳过。浏览器登录等尚无会话的认证 POST 至少校验同源 Origin 与 JSON Content-Type。

原生端将 refresh token 放系统安全存储。Capacitor 应用（安卓与后续鸿蒙）的页面来源是 https://localhost，与 API 域不同源，因此一律按原生端处理：client.kind 为 android 或 harmony，refresh_token 放请求正文并存入安全存储，不使用 Cookie 与 CSRF 机制；API 的 CORS 允许来源包含该 Capacitor 来源。本地业务数据库与待同步操作按账号隔离，登出、登录过期和重新登录均不能静默丢弃尚未同步内容。

| 模型 | 字段与默认值 |

改变 timezone 只改变这趟旅行当地日期时间的解释，不暗中平移已有计划。已有时间记录时响应 TIMEZONE_INTERPRETATION_CHANGED 警告，界面提示核对；多时区自动换算另行安排。财务 occurred_on 不随时区修改平移。

改变 currency_code：旅行存在有效账目（currency_locked_at 非空）返回 409 CURRENCY_LOCKED；尚无账目但 budget_amount 或任一有效行程项目的预计费用非空返回 409 CURRENCY_AMOUNTS_EXIST，需先清空这些金额。currency_locked_at 在第一条有效账目创建时写入、最后一条有效账目删除时清空，两次转换都递增旅行版本并进入变更流（changed_fields=['currency_locked_at']），因此删除全部账目后可以再次更改币种。

budget_amount 为 Money/null，null 表示未设置，0 表示零预算。账单页统计框的总花费与剩余预算来自 3.8 的 trip_budget，总预算的编辑走 PATCH /trips。首页按 phase 分组由客户端对列表结果本地分组完成。

账单分类按账号管理：注册时在同一事务种入六个预设（交通、住宿、美食、景点、购物、其他，图标键分别为 transport、lodging、food、attraction、shopping、other，is_preset=true）；名称在账号内唯一（去首尾空格、大小写不敏感），预设同样可改名、改图标、排序；删除是软删除，仅当没有未删除账目（含回收站旅行内的账目）引用时允许，否则 409 CATEGORY_IN_USE。分类是账号级实体，进入同步流且 trip_id 为空；P0 不开放离线管理分类。总预算是旅行字段 budget_amount，通过 PATCH /trips 修改。

退款使用同一账目接口，kind=refund。如设置 refunded_entry_id，原记录必须为同旅行的有效 expense，类别必须一致，有效关联退款合计不能超过其金额。无原支出的退款可以独立登记。原支出类别修改会同事务更新其关联退款；删除原支出时同事务将其有效关联退款的 refunded_entry_id 置空，这些退款保留为独立退款、版本递增并进入 affected，响应 warnings 含 REFUNDS_UNLINKED。

预订不会自动创建账目。票据引用同旅行、未删除的图片资产，最多 10 张，状态不限（仅 ready 的可下载）；附件数组整体替换。离线推送不允许编辑附件数组。

分摊：payer_member_id 与 participant_member_ids 必须是本旅行有效成员（否则 INVALID_REFERENCE），参与人至少 1 人且不重复。even 按参与人等分；ratio 按参与人百分比归一化，参与人百分比之和为 0 时 422（字段 participant_member_ids）。份额按币种最小单位向下取整，余数按参与人顺序逐个加一个最小单位，份额之和恒等于 amount。splits 由服务端计算并保存，修改 amount、split_mode 或参与人时重算，修改成员百分比不重算。退款的 payer 为收款人、splits 为各参与人的退回份额。

成员：PUT /members 是整体保存，需 Idempotency-Key、不需 If-Match，内部逐个比较后写入并递增被改动成员的版本，未改动的成员不写变更日志；被未删除账目引用的成员出现在删除集合时 409 MEMBER_IN_USE；is_self 成员缺失时 422；名称去首尾空格后 1–30 字、同旅行内忽略大小写唯一；百分比之和须恰好等于 100，否则 422 SHARE_PERCENT_SUM。创建旅行时同事务插入 is_self 成员「我」（100%），其 sync 变更与旅行一起进入 affected。成员不进入分享访客视图。

avatar 只接受图片；trip 接受 JPEG、PNG、WebP 和 PDF。单图上限 20 MiB，PDF 上限 50 MiB；其他图片格式由客户端转换后上传。照片说明等文字不经文件接口提交。worker 处理图片时提取 EXIF 的拍摄时间与 GPS 坐标写入 exif_* 字段（没有则为 null），只作为客户端建议，不改动任何业务记录。

完整上传流程：POST /assets（返回资产与首个上传授权）→ 建立资料/照片/票据/头像引用（可与上传并行，无需等待 ready）→ PUT 对象 → POST confirm → 通过同步事件或 GET 观察 Asset.status。授权过期或上传失败后调用 upload-authorization：当前尝试仍在确认窗口内则续签同一暂存键，否则创建新尝试；原引用与文字不受影响。

确认接口不信任客户端的“上传成功”声明。worker 读取暂存对象并校验大小、类型与摘要，记录校验时的 ETag，再以该 ETag 为条件执行服务端复制到最终对象键（按 asset_id 与 upload_attempt 确定，任务重试复用并清理失败遗留对象）；条件不满足即判定失败，等待用户重新上传。ready 后不再签发上传授权，替换文件需新建资产。缩略图失败可以保留可用原图，分别展示 thumbnail_status。

单次下载授权与批量授权只对 ready 资产签发 URL；原图与 PDF 有效 60 秒，缩略图有效 15 分钟，客户端可缓存缩略图 URL 至 expires_at。签名固定 response-content-type 与 content-disposition，文件名按 RFC 5987 编码，避免在存储域内联渲染任意内容。普通回收与永久删除覆盖全部尝试的暂存键和最终键，暂存前缀配置短期自动清理策略。

| GeoTripRouteQuery | points*（有序坐标 `经度,纬度;经度,纬度`，2–50 个点）；mode*=driving/walking/cycling |
| GeoRoute | mode、distance_meters（非负整数）、duration_seconds（非负整数）、path（GCJ-02 坐标数组）、provider="amap" |

规则：服务端持有高德 Web 服务 key，客户端不直连 Web 服务 API；每账号限流建议 60 次/分钟，另设全局日上限保护配额。逆地理编码结果按坐标四舍五入到 3 位小数（约 100 米）在服务端缓存 24 小时；地点搜索不缓存。高德短时 QPS 限流映射 429 RATE_LIMITED + Retry-After；繁忙、网络错误或超时返回 503 DEPENDENCY_UNAVAILABLE + Retry-After，表示允许有界重试。未配置、凭证／权限错误及配额不足同为 503，但提供安全的中文说明且不带 Retry-After，客户端不自动重试。结果不落库，用户确认后由客户端写入业务记录的 place_name、address、latitude、longitude；行程表单不再单独手填地点和地址。境外坐标、道路不连通或超出算路距离范围为 404 RESOURCE_NOT_FOUND，按“无结果”处理，不伪造路线。单实例同一 Web 服务 Key 的算路串行发起，默认至少间隔 1.1 秒；排队取消不消耗配额，排队后再查缓存以合并相同路段。**整趟算路走 /geo/trip-routes**：驾车按高德路径规划 2.0 的途经点能力每 16 段（17 个坐标）合并为一次上游请求，返回的整条路线按每一步的起点下标归属到各段，各段距离与时长是各步之和（仍是高德口径，段与段首尾相接）；上游未返回步骤级明细、坐标超过 50 个或任一段无法确定时整体失败，调用方退回逐段算路，保持「单段失败只计一段」的既有降级。批量与单段共用同一份路段缓存（模式 + 有序坐标，5 分钟）。前端每段最多重试两次，遵守 Retry-After；等待建议超过 8 秒则交还用户稍后重算，避免长时间挂起或反复撞限额。

地图底图与选点用高德 JS API 2.0；公开的 JS API key 由 VITE_AMAP_JS_KEY 配置，安全密钥仅由服务端 /_AMapService 代理追加，该路径对 Capacitor 来源返回 CORS 头。POI 搜索、逆地理编码与算路通过带账号身份的 /geo 接口。逆地理编码缓存复用地址但不得替换本次请求的坐标；路线按有序起终点（6 位小数）与模式缓存 5 分钟。路线按用户的行程顺序连接，不自动重排；未定位项目显式提示，无法算路时只画带说明的示意连线，不计入道路里程。实现与验证边界见 `docs/architecture/2026-09-14-高德地图与行程路线.md`。移动端系统定位及 EXIF 的 WGS-84 坐标在采用前转换为 GCJ-02；导航可拉起高德应用。

## 4. 同步协议

### 4.1 推送

SyncPush = {client_id:UUID, operations:SyncOperation[]}。每个操作：

- operation_id: UUID；type: 下表允许值；entity_id: UUID；trip_id: UUID。
- base_version: ledger_entry.update 必须提供 Version；创建、packing_item.set_status、todo.set_completed 使用 null。
- payload: 对应业务创建/编辑字段；id 由 entity_id 表达，不重复放入 payload。
- depends_on: 本批较早操作的 operation_id 数组，默认 []，不接受前向引用或循环。

| type | payload | 边界 |
| --- | --- | --- |
| ledger_entry.create | LedgerCreate 去掉 id 和 attachment_asset_ids | 可新增支出和退款；category_id 必须是本账号有效分类，否则 rejected INVALID_REFERENCE |
| ledger_entry.update | LedgerPatch 去掉 attachment_asset_ids | 按 1.2 的字段级合并规则处理基线落后 |
| packing_item.set_status | {status: pending/ready/packed} | 无基线版本，最后写入生效并递增版本；不离线创建/删除物品 |
| todo.set_completed | {completed: boolean} | 无基线版本，最后写入生效并递增版本；不离线改截止日期或删除 |

操作入队后内容不可修改，重试必须原样重发；服务端对已成功的 operation_id 返回 replayed，这就是查询重试结果的方式，不设单独查询接口。离线新建实体的版本链是确定的：创建后版本为 1，本设备后续每次更新加 1，直到收到其他设备对该实体的变更；客户端据此填写后续 update 的 base_version，不猜测其他值，也不用 depends_on 跳过版本校验。同一实体的创建与后续更新是独立操作，不合并。

SyncPushResult = {results:[{operation_id,status,result?,error?}]}；status 为 applied、replayed、conflict、rejected、dependency_failed、failed。业务冲突放在逐操作结果中，整批 HTTP 200；身份失败、格式错误或超限才在顶层返回错误。result 为 WriteResult（含 data）；applied 且 warnings 含 MERGED_WITH_NEWER_VERSION 表示合并应用。error 包含与 REST 一致的 code、http_status、retryable 和冲突内容：failed 表示数据库超时、依赖不可用等瞬时故障，retryable=true，客户端保留该操作原样重试；rejected 与 conflict 的 retryable=false。

  "operations": [
    {
      "operation_id": "019ed632-51c0-7000-8000-000000000001",
      "type": "ledger_entry.create",
      "entity_id": "019ed632-51c0-7000-8000-000000000002",
      "trip_id": "019ed632-51c0-7000-8000-000000000004",
      "base_version": null,
      "depends_on": [],
      "payload": {
        "kind": "expense",

### 4.2 拉取、批次与游标

SyncChangesQuery：cursor 必填；limit 默认 200、最大 500。首次使用需要完成 baseline 快照；不提供按旅行过滤参数。

SyncChangesPage：

```json
{
  "changes": [
    {
      "seq": "145",
      "batch_id": "019ed632-51c0-7000-8000-000000000001",
      "batch_end_seq": "145",
      "entity_type": "ledger_entry",
      "entity_id": "019ed632-51c0-7000-8000-000000000002",
      "trip_id": "019ed632-51c0-7000-8000-000000000004",
      "version": "1",
      "kind": "upsert",
      "schema_version": 1,
      "requires_snapshot": false,
      "changed_fields": ["kind", "amount", "category_id", "occurred_on", "notes", "refunded_entry_id", "attachment_asset_ids"],
      "data": {
        "id": "019ed632-51c0-7000-8000-000000000002",
        "trip_id": "019ed632-51c0-7000-8000-000000000004",
        "kind": "expense",
        "amount": "128.50",
        "currency_code": "CNY",
        "category_id": "019ed632-51c0-7000-8000-000000000005",
        "occurred_on": "2026-09-11",
        "notes": "午餐",
        "refunded_entry_id": null,
        "attachment_asset_ids": [],
        "version": "1",
        "created_at": "2026-09-11T04:30:00Z",
        "updated_at": "2026-09-11T04:30:00Z",
        "deleted_at": null
      }
    }
  ],
  "next_cursor": "opaque-next-cursor",
  "has_more": false
}
```

变更条目与 sync_changes 列的映射：seq ↔ seq；batch_id、batch_end_seq、entity_type、entity_id、trip_id、schema_version、requires_snapshot 同名；version ↔ entity_version；kind ↔ change_kind；changed_fields ↔ changed_fields（upsert 为该版本实际变化的字段名数组，创建时为全部业务字段；delete/purge/redacted 为 null）；data ↔ snapshot（upsert 时为与对应 GET 资源相同的白名单结构，含派生的 currency_code；其余为 null）。entity_type 取值：expense_category、trip、trip_member、itinerary_item、packing_item、todo、ledger_entry、reservation、document、photo、asset；其中 expense_category 是账号级实体，其 trip_id 为 null，客户端无论是否选择离线旅行都要保留。

一次拉取轮次的游标内部固定账号和上界，分页不能不断扩大上界。只有上一页已持久化后才能请求 next_cursor；本地应用完整批次后更新其应用进度，扫描进度和应用进度分别保存。重启后可继续未完成批次，不重复应用已确认版本。

delete 表示逻辑删除；purge 表示永久清理；这两者的 data=null。redacted 表示此前历史正文已被清除，只推进扫描，不执行实体写入。trip 的 delete/purge 作用于该旅行的完整本地范围，并保留尚未同步的用户修改到冲突区。

SyncStatus 返回 protocol_version=1、server_time、retention_days=90、has_changes 的可选提示；它不提供可直接跳转的新游标。游标签名错误或属于其他账号返回 INVALID_CURSOR；合法但过期返回 CURSOR_EXPIRED。

### 4.3 快照模型

| 模型 | 字段 |
| --- | --- |
| SyncSnapshotCreate | purpose*: baseline/trip_reload；selected_trip_ids*: UUID[]，去重；baseline 可为空以仅同步账号级分类与旅行列表，trip_reload 至少一趟 |
| DataSnapshot | id、purpose、selected_trip_ids、status: queued/building/ready/failed/invalidated/expired、item_count、captured_at/null、expires_at、schema_version、error_code/null；ready 时返回 baseline_cursor |
| SnapshotPageQuery | cursor 可空；limit 默认 200、最大 500 |
| SnapshotPage | items:[{ordinal,entity_type,entity_id,trip_id,version,data}]、next_cursor、has_more、baseline_cursor |

purpose=export 的快照不能通过客户端快照接口读取。ready 快照分页稳定；items 接口在 queued/building 返回 409 SNAPSHOT_NOT_READY，failed 返回 409 SNAPSHOT_FAILED（需重新创建快照），expired 返回 410 SNAPSHOT_EXPIRED，invalidated 返回 410 SNAPSHOT_INVALIDATED。baseline_cursor 即该快照的同步上界，仅完成 baseline 全部数据核对后可采用；trip_reload 中只作为参照，不能推进全局同步进度。

baseline 请求中已被永久删除的本账号旅行 ID，可根据墓碑从选定详情范围中剔除；回收站旅行只返回基础信息。响应 selected_trip_ids 表示实际可下载详情的集合，客户端根据完整旅行清单核对缺失范围并保留未同步修改。其他账号或从未属于本账号的 ID 返回 404。trip_reload 的目标必须是当前有效旅行。

客户端核对阶段必须保留待同步操作、原始基线、已确认删除标记和比快照更新的版本。补充快照不能使已处理的新删除事件失效，也不能重新出现已永久删除的旅行。

## 5. 导出、回收站与注销模型

| 模型 | 字段 |
| --- | --- |
| ExportCreate | format*: trip_archive/expense_csv；scope*: all/selected；selected 时 trip_ids*: 非空 UUID[]；expense_csv 可传 filters:{date_from?,date_to?,category?}，trip_archive 不接受筛选 |
| ExportJob | id、format、scope、selected_trip_ids、filters、status、processed_items、total_items/null、captured_at/null、created_at、finished_at/null、expires_at/null、byte_size/null、error_code/null；filters 回显请求时采用的筛选，trip_archive 为空对象 |
| ExportDownloadAuthorization | url、expires_at、file_name、media_type、byte_size；有效 60 秒，响应 Cache-Control: no-store |
| PurgeTripRequest | confirm*: true；在本人回收站旅行上执行，需 If-Match、幂等键和本会话近期认证 |
| AccountDeletionRequest | confirm*: true；需账号 If-Match、幂等键和本会话近期认证；不接收客户端指定账号 ID |
| AccountDeletionResult | result: WriteResult、job_id、receipt_token、receipt_expires_at |
| DeletionReceipt | job_id、receipt_token、receipt_expires_at；补领时旧凭证失效 |
| DeletionJob | id、scope、status、stage、processed_items、total_items/null、created_at、started_at/null、finished_at/null、error_code/null；不返回原始对象键或数据库细节 |

旅行恢复须在 purge_after_at 前且 purge_requested_at 为空；服务端按时间与锁内状态判定。进入永久清理后返回 RESTORE_UNAVAILABLE，不以用户设备时间为准。

注销只读凭证至少 256 位随机数，仅以 Authorization: Deletion <receipt_token> 传输，不放 URL。它只授权对应账号注销任务的 GET，不能用于旅行接口或重新执行清理。GET 路由不要求已删除账号仍存在。任务与凭证最迟在完成 7 天后清理，后续查询返回 410。

账号注销请求成功后，客户端先可靠保存只读凭证再结束普通会话。响应丢失但仍持有效会话时，可以在 deleting 状态下调用 receipt 补领；禁止此通道访问旅行。若首次注销请求被重复送达，使用同一幂等键返回同一任务，凭证按当前授权情况重新签发，不从日志或操作收据恢复秘密。

## 6. 元数据与默认值

Metadata 至少包含 protocol_version、支持的 currency 列表及 minor_units、默认币种 CNY、账单分类可用的图标键集合、物资类别/状态、行程类别/状态、预订类别、物品库版本、上传 MIME 与大小上限、地图供应商 amap 与坐标系 GCJ-02。客户端不能自行添加服务端未支持的枚举值。

初始币种集合：CNY、USD、EUR、GBP、JPY、HKD、MOP、TWD、KRW、SGD、THB、MYR、IDR、VND、AUD、CAD、CHF、NZD、AED、KWD、BHD。其中 JPY/KRW/VND 为 0 位，KWD/BHD 为 3 位，其余为 2 位。P0 不提供汇率换算；币种清单作为版本化内置数据维护。

所有动态默认日期由服务端按旅行 timezone 计算；离线客户端在创建操作时就记录明确的 occurred_on/recorded_on，重连时不能把日期改为上传当天。实际被写入的默认字段会出现在后续资源 GET 与同步快照中。
